#### پیش‌فرض برنامه:

ip_all

(اسکنر آی‌پی روی همه کانفیگ‌ها)


#### ۱) اسکنر آی‌پی · همه کانفیگ‌ها

mode=ip_all

چه کار می‌کند؟

برای هر لینک داخل

links.txt

، همه آی‌پی‌های

cfip.txt

را یکی‌یکی داخل کانفیگ می‌گذارد و تست می‌گیرد.

یعنی اگر ۳ کانفیگ و ۱۰ آی‌پی داشته باشید:

text۳ × ۱۰ = ۳۰ تست

ورودی لازم

links.txt
cfip.txt

مناسب برای

پیدا کردن بهترین ترکیب کانفیگ + آی‌پی کلادفلر
اسکن کامل و دقیق

نکته
زمان‌برترین حالت است؛ با
max_ips
و
workers
می‌توانید سبک‌ترش کنید.

### ۲) اسکنر آی‌پی · کانفیگ انتخابی
mode=ip_one

چه کار می‌کند؟
فقط یک کانفیگ را انتخاب می‌کنید؛ بعد همه آی‌پی‌های لیست فقط با همان کانفیگ تست می‌شوند.
مثال: کانفیگ شماره ۰ + ۲۰ آی‌پی → ۲۰ تست.
ورودی لازم


links.txt (حداقل یک لینک)

cfip.txt

انتخاب کانفیگ از منو (یا config_index=0 در CLI)

مناسب برای

وقتی یک کانفیگ خوب دارید و فقط می‌خواهید بهترین آی‌پی کلادفلر را برای همان پیدا کنید
سریع‌تر از حالت همه کانفیگ‌ها


### ۳) فقط بنچمارک کانفیگ

mode=config_only

چه کار می‌کند؟
لیست آی‌پی کلادفلر نادیده گرفته می‌شود.
هر لینک با آدرس اصلی خودش (همان host داخل لینک) تست می‌شود.
ورودی لازم

فقط links.txt

مناسب برای

مقایسه چند کانفیگ مختلف با هم
وقتی آی‌پی کلادفلر مهم نیست و می‌خواهید کیفیت خود کانفیگ را بسنجید


### ۴) فقط اینترنت کاربر

mode=baseline_only

چه کار می‌کند؟
بدون هیچ پروکسی، بدون کانفیگ، بدون آی‌پی کلادفلر:
فقط اینترنت مستقیم سیستم شما را اندازه می‌گیرد (تأخیر، دانلود، آپلود و امتیازها).
ورودی لازم

هیچ‌کدام از links.txt / cfip.txt الزامی نیست

مناسب برای دیدن سقف واقعی سرعت خط خودتان
مقایسه بعدی: «پروکسی چقدر از خط مستقیم ضعیف‌تر است؟»


### ۵) تست مستقیم آی‌پی کلادفلر

mode=cf_direct

چه کار می‌کند؟ بدون لینک کانفیگ و بدون روشن کردن

Xray:

هر آی‌پی کلادفلر را مستقیم با روش نزدیک به relay
پروب می‌کند، مثلاً:

اتصال
TCP
به پورت
443
درخواست
HTTP/HTTPS
به خود آی‌پی

ورودی لازم

فقط cfip.txt

مناسب برای غربال سریع آی‌پی‌های مرده یا خیلی کند،  قبل از اسکن سنگین با کانفیگ

#### نکته
این حالت کیفیت پروکسی واقعی را نشان نمی‌دهد؛ فقط زنده بودن و تقریبی بودن پاسخ آی‌پی را می‌سنجد.

## حالت‌های اجرا

| حالت | CLI | معنی |
|------|-----|------|
| اسکنر آی‌پی · همه کانفیگ‌ها (**پیش‌فرض**) | `mode=ip_all` | هر کانفیگ × همه آی‌پی‌ها |
| اسکنر آی‌پی · کانفیگ انتخابی | `mode=ip_one` و `config_index=N` | یک کانفیگ × همه آی‌پی‌ها |
| فقط بنچمارک کانفیگ | `mode=config_only` | آدرس اصلی لینک؛ بدون لیست آی‌پی |
| فقط اینترنت کاربر | `mode=baseline_only` | فقط خط مستقیم بدون پروکسی |
| تست مستقیم آی‌پی کلادفلر | `mode=cf_direct` | پروب TCP/HTTP بدون لینک و بدون Xray |

مثال:

```bash
python cf_xray_benchmark.py mode=ip_all workers=1
python cf_xray_benchmark.py mode=ip_one config_index=0 max_ips=20
python cf_xray_benchmark.py mode=config_only
python cf_xray_benchmark.py mode=baseline_only
python cf_xray_benchmark.py mode=cf_direct
```

در
 GUI
از منوی **حالت اجرا** انتخاب کنید. برای حالت انتخابی، منوی **انتخاب کانفیگ** را هم تنظیم کنید.

## تنظیمات
 config.json

کلیدهای شروع‌شده با
 `_`
فقط توضیح هستند.

| بخش | کاربرد |
|-----|--------|
| `mode` | یکی از حالت‌های اجرا |
| `config_index` | ایندکس کانفیگ برای `ip_one` |
| `workers` | تعداد همزمان |
| `max_ips` | سقف تعداد آی‌پی (`0` = همه) |
| `filter.*` | پروب سریع و سقف پینگ |
| `tests.*` | latency / download / upload |
| `relay.*` | سایت‌های رله |
| `scoring.*` | امتیازها و وزن Overall |
| `ranking.*` | تعداد و نمایش جداول برتر |
| `timeouts.*` | مهلت HTTP و استارت اکسری |
| `excel.enabled` | خروجی اکسل |

آرگومان‌های
 CLI
در صورت دادن، روی فایل تنظیمات اولویت دارند.
